How it works

Your computer, reachable anywhere. Sektar can run on a computer at home. A secure tunnel gives it your own address, and the connection stays encrypted end to end.

Backups. Encrypted copies go to the cloud every day. For now Sektar holds the key so we can help you restore; holding it yourself comes next.

AI, your choice. Each agent runs where you say: on your computer, in an EU cloud, or with a frontier model for the tasks that need one.

A record of every change. Everything you or your agents change is signed and kept, so you can see it and undo it.

    How sign-in and forwarding work

    1. This page gets its own key
      An ECDSA P-256 key made with WebCrypto and kept in IndexedDB (sektar-site). Its did:key:zDn… is the app and connect id Renown signs a credential for.
    2. Renown signs in and returns
      www.renown.id/?app=&connect=&network=eip155&chain=1&returnUrl=. It comes back with ?user=did:pkh:eip155:1:0x….
    3. The page checks the credential
      GET /api/auth/credential: it must be issued by that address to this page's DID and not be expired. The EIP-712 signature is recovered with viem (from jsDelivr) and must match the issuer. The profile comes from POST /api/profile.
    4. Find the environment
      In order: ?env= in the link, a directory (not built yet, see right), environments remembered on this device, or the address the person types.
    5. Forward
      For a home computer the page first checks the address answers, so a sleeping computer gets a clear message instead of a browser error. Then it navigates. Connect there signs in with Renown again, against its own key; Renown has a session, so that's one approval.
    My computer (Portle)https://app.<zone>/: a customer zone such as marit.studio, or a shared one, <siteId>.sites.portle.host. TLS ends on the computer; the relay can't decrypt.
    Sektar cloud (Vetra)https://connect.<env>.vetra.io/, after the Vetra Cloud docs. The delivery study proposes <name>.sektar.app; change VETRA_URL in js/site.js when it's settled.
    Directory (missing)No API maps a Renown user to their environments yet. Proposed: GET {directory}/v1/environments?owner=did:pkh:… → {environments:[{name, kind, connectUrl}]}, served by Vetra and fed by the Portle plugin. Set DIRECTORY_URL in js/site.js and the page uses it.
