# Where Sektar runs

You can run Sektar in three ways. They differ in who keeps it running and where your documents are.

Sektar Cloud and Self-hosted Sektar are the same software. The only difference is who runs it: we do, or you do. The Sektar Desktop App is built differently: it keeps everything on your computer, and you use it on that computer.

Each one is a separate Sektar. Documents don't sync between them.

|  | Sektar Desktop App [Download](/download) | Sektar Cloud [Open my Sektar](/login?want=vetra) | Self-hosted Sektar [Set it up](#self-hosted-sektar) |
| --- | --- | --- | --- |
| What it is | An app you install on your computer | Your own Sektar, hosted for you on Vetra | Sektar in containers, on a server you run |
| How you start | Download the installer for macOS (Apple silicon), Windows or Linux (.deb) | Sign in with Renown and enter an invite code | Build the image from the [source code](https://github.com/powerhouse-inc/sektar) and start it with Docker Compose |
| Without internet | Your documents stay available. Connected accounts wait until you're back online | Not available | You can't sign in |

Connected accounts on Sektar Cloud aren't fully working yet: a new environment can sign in to Google and read from it, but can't save what it reads.

The downloaded Desktop App comes with Sektar's Google sign-in, so it can connect Gmail and Google Calendar. <Planned />

Google hasn't verified Sektar's app yet, so only accounts on our test list can connect Gmail or Google Calendar.

To try Sektar first, use the free option on the [home page](/#start). It runs in a browser tab and keeps your documents in that browser.

## Sektar Desktop App

Download the installer for your computer from the [download page](/download). Sektar isn't signed by a registered developer yet, so your computer asks you to confirm before you open it the first time. <Planned />

- **macOS (Apple silicon):** open the `.dmg` and drag Sektar into Applications. The first time you open it, macOS says it can't check it for malicious software. Open **System Settings**, then **Privacy & Security**, and choose **Open Anyway**.
- **Windows:** run the installer. If SmartScreen stops it, choose **More info**, then **Run anyway**.
- **Linux:** install the `.deb`.

To update, install the new version over the old one. Your identities and documents stay where they are. <Planned />

### Signing in

Sektar asks who you are when it starts, before anything else runs. <Planned />

- **Renown** is the recommended way. Your browser opens so you can approve Sektar. Once you've signed in, Sektar also works without internet.
- **A local key** is an Ethereum key kept on your computer, protected by a password. It needs no account and no internet.

The identity you choose is the admin of that Sektar.

### Where your documents are

Each identity has its own folder and its own documents. <Planned />

```
settings.json     settings shared by every identity
local.key         the local key, encrypted with your password
local/            the local identity
0x…/              a Renown identity, by its address
```

Every identity folder holds `.ph`, the storage itself, and `backups`. It also keeps a copy of your public profile, so Sektar can show your name when it's offline.

`.ph` also holds what your automations keep: their downloads, and the key that protects your connected accounts. So a copy of an identity's folder can use those accounts, and needs the care you'd give a password. <Planned />

Changing Renown identity takes you to that identity's documents. Replacing the local key keeps yours, so if you forget the password, replace the key.

The password protects the key, not your documents, which aren't encrypted on disk.

The first screen shows which folder your documents are in, and you can change it there. It's best not to use a folder that syncs, such as OneDrive or iCloud Drive: a live database can be damaged there. If the folder is on a drive that's been unplugged, Sektar says so and doesn't start with an empty one.

### Closing Sektar

Closing the window leaves Sektar running in the tray, so your automations carry on. To stop it, choose Quit from the tray icon, or set `window.closeQuits` below. Sektar closes its databases first, which normally takes a second or two, so the next start has nothing to repair. <Planned />

### Settings

`settings.json` applies to every identity, and Sektar reads it when it starts. Everything in it is optional. <Planned />

| Setting | What it does | If you leave it out |
| --- | --- | --- |
| `memory.mainMb` | Memory for Sektar itself | Set from your computer's memory |
| `memory.workflowWorkerMb` | Memory for each automation | Set from your computer's memory |
| `memory.pgliteWorkerMb` | Memory for each database worker | Sektar's default |
| `concurrency.workflowRuns` | Automations that run at once | Sektar's default |
| `renown.url` | The Renown instance to use | The official one |
| `renown.switchboardUrl` | That instance's switchboard | Found from `renown.url` |
| `registryUrl` | Where add-ons come from | Sektar's default |
| `logLevel` | How much goes in the logs | `info` |
| `startupTimeoutSeconds` | How long Sektar may take to start | 180 |
| `automations` | Set to `false` to start with automations off, if one is stopping Sektar from starting | `true` |
| `telemetry.diagnostics` | Diagnostics, kept on your computer | `true` |
| `telemetry.errorReports` | Error reports sent to us | `false` |
| `window.closeQuits` | Closing the window quits Sektar | `false` |

Sign-in, ports and secrets can't be set here. A `settings.json` that can't be read stops Sektar from starting, and it tells you why.

### Telemetry

Nothing leaves your computer unless you turn on `telemetry.errorReports`. <Planned />

Diagnostics stay on your computer, in `.ph/telemetry`, so you can look at them or send them to us if something goes wrong. Turn them off with `telemetry.diagnostics`.
